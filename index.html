Megvii-BaseDetection / YOLOX
Pull Request #1869

Fix MPS (Apple Silicon) Backend Inference Crash & Device Alignment

Identified and patched a framework-level bug causing runtime execution failure of YOLOX object detection models on Apple Silicon (M1/M2/M3/M4) devices when executing PyTorch's Metal Performance Shaders (MPS) backend.

The Challenge

Legacy PyTorch calls to Tensor.type() return 'torch.mps.FloatTensor' on macOS devices, which is not registered in the framework's type casting map, crashing inference. A secondary bug in decode_outputs() generated coordinate grid/stride tensors on the CPU instead of allocating them on the active MPS device, producing a device-mismatch RuntimeError.

The Solution

Modernized device/type handling across yolo_head.py: switched legacy type-string checks to Tensor.dtype objects and resolved device alignment by using device-aware .to(device=..., dtype=...) syntax. Verified backward compatibility on standard CUDA/CPU configurations.

Location Legacy Code (Crashed on MPS) Modern API (MPS / CUDA / CPU)
yolo_head.py: L211 xin[0].type() xin[0].dtype
yolo_head.py: L223 .type(dtype) .to(device=output.device, dtype=dtype)
yolo_head.py: L245-246 .type(dtype) .to(device=outputs.device, dtype=dtype)
Verified on Apple M2 (macOS): YOLOX-X MOT20 inference runs successfully at ~1.7 FPS
